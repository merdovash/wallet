# Float button основного действия

Документ фиксирует паттерн **одной основной кнопки** на экран: на телефоне это FAB (плавающая кнопка), на десктопе — primary в шапке страницы или панели.

Источник: задача 91 в [`TASKS.md`](TASKS.md). Связанные пункты лога: 47 (смахивание панелей), 64/66/68 (сохранение чек-ина на ПК), 79 (кнопка «Чек-ин» не вмещалась в адаптив дашборда), 86 (напоминание не заменяет FAB), 87 (навигация), 88 (панель чек-ина всегда в режиме ввода).

Граница экранов: Tailwind `md` (768px). Ниже — мобильный паттерн, `md` и шире — десктопный.

## 1. Зачем одна кнопка

Чек-ин — главное действие приложения. Отдельная кнопка в шапке дашборда на узком экране не вмещалась рядом с фильтрами (задача 79). Решение:

- **одно** основное действие на контекст;
- на мобиле оно всегда в одном месте (правый нижний угол над нижней навигацией);
- на десктопе — справа в шапке, без FAB;
- вторичные кнопки не конкурируют с primary за место.

Баннер напоминания о чек-ине на дашборде (задача 86) — вспомогательный вход, не замена FAB.

FAB рисуется только когда пользователь вошёл и кошелёк загружен.

## 2. Два варианта одной кнопки

| | Мобиле (`< md`) | Десктоп (`≥ md`) |
|---|-----------------|------------------|
| Где | только FAB | только кнопка в `PageHeader` / шапке `EntityEditPanel` |
| Primary в шапке страницы | нет (`hidden`, без `inline-flex`) | да (`md:inline-flex`) |
| FAB | да (`flex`) | нет (`md:hidden`) |
| Вторичные действия | на странице как обычно | **слева** от primary |

Нельзя вешать на одну кнопку сразу `inline-flex` и `hidden`: в Tailwind побеждает порядок в CSS, и шапка остаётся видимой рядом с FAB. Видимость задаёт только вариант: toolbar = `hidden md:inline-flex`, FAB = `flex md:hidden`.

Позиция FAB: `right-4`, `bottom: 4.75rem + safe-area-inset-bottom` — над нижней навигацией. У `main` на мобиле запас снизу `7rem + safe-area`, чтобы контент не уезжал под кнопку.

Внешний вид FAB: круглая синяя кнопка (`h-14`, `rounded-full`), подпись действия; для чек-ина — иконка календаря с галочкой.

### 2.1. Экранная клавиатура

FAB **всегда виден**: при открытой клавиатуре он поднимается и стоит над ней, а не остаётся под оверлеем клавиатуры.

Как считается:

1. Слушаем `visualViewport` (`resize` / `scroll`) и фокус полей ввода.
2. Перекрытие = `innerHeight − visualViewport.height − visualViewport.offsetTop` — сколько layout-экрана скрыто снизу.
3. Если в фокусе поле ввода и перекрытие ≥ 64px (реальная клавиатура, не строка URL), `bottom` = перекрытие + 12px — сразу над клавиатурой. Нижняя навигация в этот момент тоже под клавиатурой, её зазор не добавляем.
4. Если layout сам сжался (типичный Android Chrome), перекрытие ≈ 0 — оставляем CSS-позицию: `fixed; bottom: 4.75rem` уже уезжает вверх вместе с вьюпортом.

На десктопе (`≥ md`) FAB нет, правило не применяется. `transition` только на цвет, чтобы `bottom` не отставал от анимации клавиатуры.

## 3. Что делает кнопка

Приоритет (сверху вниз):

1. **Панель редактирования** (`scope: 'panel'`) — «Сохранить» сущности.
2. **Переопределение раздела** (`scope: 'section'`) — например «Добавить счёт».
3. **По умолчанию** — новый чек-ин (`openCreate` из `checkInUiStore`).

### 3.1. По разделам

| Раздел | Основное действие | FAB на мобиле | Primary в шапке на десктопе |
|--------|-------------------|---------------|-----------------------------|
| Дашборд | Чек-ин | да | да |
| Чек-ины | Чек-ин | да | да |
| Аналитика и отчёты (по дням, типам, валютам, помесячно, float, кэшбек) | Чек-ин | да | да |
| Счета | Добавить счёт | да | да |
| Настройки | нет | скрыт | скрыт (`showPrimary={false}`) |

На странице «Чек-ины» кнопка «Перевод» — вторичная, слева от «Чек-ин». На «Счетах» «Показать архив» — тоже вторичная.

Пока открыта панель чек-ина, секционный primary («Чек-ин» / «Добавить счёт») скрывается: его место занимает «Сохранить».

## 4. Панели: просмотр vs редактирование

Два типа панелей (`StackPanel`, задача 47: на мобиле смахивание вниз закрывает; задача 102: на десктопе панель справа):

### 4.1. Просмотр (`StackPanel` без Save)

Расшифровка прироста, день, курсовая разница, реестр курсов.

На **мобиле** — нижний sheet. FAB чек-ина **не убирается из DOM**, а оказывается **под** sheet: слой панели `z-[100]`, слой FAB раздела `z-[90]`. Пока sheet открыт, основное действие страницы недоступно.

На **десктопе** (`md+`) панель выезжает **справа**, ширина до 32rem, без индикатора свайпа, закрытие — кнопка «Закрыть». Секционный primary в шапке страницы остаётся (панель его не перекрывает целиком).

### 4.2. Редактирование (`EntityEditPanel`)

Чек-ин, счёт, карточка счёта (остаток на сегодня), перевод, перевод внутри чек-ина.

Общий хром: заголовок, **Закрыть**, контент. Меняются только поля и `onSave`.

| | Мобиле | Десктоп |
|---|--------|---------|
| Сохранить | FAB поверх sheet (`z-[110]`) | кнопка в шапке панели (`md:inline-flex`, на мобиле скрыта) |
| Закрыть | в шапке панели | в шапке панели |

`EntityEditPanel` регистрирует override `scope: 'panel'`. Пока overlay жив, FAB = Save, даже если под ним другой секционный override.

## 5. Вложенные панели

Одновременно может быть несколько `EntityEditPanel`. Save должен принадлежать **верхней**.

Правило: нижняя панель ставит `saveActive={false}`, пока открыта вложенная.

Сейчас: чек-ин (`saveActionId: check-in-save`) + карточка перевода (`check-in-transfer-save`). Пока открыт редактор перевода, FAB/Save шапки чек-ина не активны; Save принадлежит переводу. Закрытие верхней панели возвращает Save чек-ину.

У каждой панели свой `saveActionId`, чтобы снятие регистрации не сбрасывало чужой override.

## 6. Чек-ин и переводы

Отдельной кнопки «Чек-ин» на дашборде нет — только FAB / primary шапки (и баннер напоминания).

Панель чек-ина всегда форма ввода (задача 88): текущий остаток — плейсхолдер, пустое поле = без изменений.

**Добавить перевод** — не primary. Кнопка вверху карточки чек-ина (если активных счетов ≥ 2). Создание и правка перевода — отдельная карточка (`CheckInTransferPanel`). После сохранения список переводов в чек-ине прокручивается к новой строке (`data-transfer-anchor`).

Сохранение чек-ина на десктопе: кнопка в шапке панели и submit формы по Enter (задачи 64, 66, 68). Клики по кнопкам шапки не должны проваливаться в backdrop.

На странице «Чек-ины» отдельная панель «Новый перевод» создаёт чек-ин с пересчитанными остатками; её Save — тот же паттерн `EntityEditPanel`.

## 7. Слои (z-index)

Снизу вверх:

| Слой | z | Что |
|------|---|-----|
| Нижняя навигация | 50 | таббар |
| Мобильное меню | 55 | drawer |
| FAB раздела | 90 | Чек-ин / Добавить счёт |
| Sheet | 100 | любая `StackPanel` |
| FAB панели | 110 | Сохранить |

Просмотровая панель перекрывает FAB раздела. Save редактирования всегда над своим sheet.

## 8. Как добавлять экран или панель

**Новый раздел с чек-ином как основным действием** — ничего не регистрировать: `PageHeader` + глобальный `PrimaryFab` уже дают нужную кнопку. Не ставить вторую кнопку «Чек-ин» в контент.

**Другое основное действие раздела** — `useRegisterPrimaryAction` с `scope: 'section'`, пока панель создания/редактирования закрыта (как «Добавить счёт»).

**Раздел без основного действия** — `PageHeader showPrimary={false}` и не регистрировать override (настройки).

**Форма сущности** — только `EntityEditPanel`, не собирать Save/Close вручную. На мобиле Save сам уйдёт в FAB.

**Вложенная форма** — у нижней `saveActive={false}`, у верхней свой `saveActionId`.

**Просмотр** — голый `StackPanel`, без регистрации Save. FAB чек-ина останется под overlay.

Вторичные действия всегда через `PageHeader actions` (на десктопе они встанут слева от primary) или внутри контента, не дублируя FAB.
